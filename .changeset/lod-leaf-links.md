**LOD draws a link between two kept leaves as LOD off draws it.** With LOD on, each frame used to gather every link from its glyphs' rows. A view that keeps (nearly) every node as a leaf paid that for every graph edge: a cold disc start's seed frame under the overlap rule, or any spread-out layout. Now only the links that touch an aggregate are gathered. A link between two kept leaves is drawn by its edge id on WebGL. The full-detail path's per-edge width, colour, radii, bend and highlight columns stay on the GPU as tables, built once per style. Each frame uploads only the shown links' edge ids and ends: 20 B per link, plus 4 B for a fade inside a cross-fade band. The link shaders are the ones LOD off draws with; they read their style from the tables. A view where every node is a leaf has the same pixels with LOD on and off, and link picking returns LOD off's hit for such a link. Canvas/SVG draw the same links from the same columns.

The link gather lists these links as it reads the kept leaves' own edges (no second walk), and they are sorted into edge order, the order LOD off draws them in, so overlapping links stack the same way. The cost follows the shown leaves, not the graph. An aggregated view that keeps no leaf link draws zero instances and uploads nothing for them. The tables and the per-instance buffers are built once, when the LOD lane registers, so no GPU object is created while the view or the layout changes. GPU memory, per edge: 21 B of tables for lines, 37 B for half-arrows, 58 B for lines with arrowheads, plus 24 B per link layer for the per-instance buffers (lines with arrowheads are two layers). That is about what LOD off holds for its links. The CPU keeps no copy of the tables. It holds 8 B per edge for the walk's edge map and 4 B per edge and layer for the fade buffer's source, plus 1 B per edge of selection flags while a selection is active.

New, for low-level users: `InstancedLinesData` / `InstancedArrowsData` / `InstancedHalfArrowsData` take `index` + `tableCount` (+ `fade`) for an indexed draw. The optional backend method `orderInstancedLayers` lets the engine keep a lane's unchanged layers when the set of layers changes, instead of recreating them. `superEdgeStats` reports `leafLinks`, and `leafEntries`: the CSR entries a separate walk read to list them (0 where the gather listed them, on the spatial tree).
