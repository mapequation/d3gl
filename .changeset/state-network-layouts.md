State networks keep a layout per view (#495):

- **The state view is the plain network over the state graph and its modules**, exactly what `data(stateGraph, { modules })` gives: `lod()` cuts its module tree by default (with `moduleBoundary` rings), `layout({ nested })` lays it out by module, and hits carry the module `path`. `stateNetwork()` now checks `modules` as `data()` does (a record for every state node, exactly once) and throws on a misaligned assignment.
- **Each view keeps its own layout.** `layout()` lays out the view on screen like a plain network's: the physical graph in the physical and both views, which share that layout, the state graph in the state view. A view switch keeps every view's positions; a view never laid out is laid out when it is first shown, with the app's last `layout()` options, from where its nodes are (the state nodes from around their physical node); a run a switch interrupted goes on when its view is shown again, over the ticks it had left and at the heat it had reached (no reheat). Each layout keeps its camera too: a view shown again comes back at the pan and zoom it was left at (the physical and both views share theirs), and a view shown for the first time is framed by its first layout's `fit`. `stopLayout()` stops every view's layout: no view goes on with a run on its own afterwards. **Breaking:** `layout({ backend: "positions", positions })` in the state view takes the state nodes' positions (it took the physical ones), and throws on a length that does not match the view's graph.
- **The both view keeps each state node's place in its physical node**, which follows the physical layout; a state node dragged there stays inside its physical node and keeps that place. New `net.positions`: the positions of the view on screen (in the both view the state nodes', which no graph holds; see #509 for screen mode).
- **A drag reheats the layout of the view it is in**, also after a view switch, on the force, worker and GPU backends; in the both view a physical node drag reheats the physical layout and its state nodes ride along. One coordinate scale (#401): a layout without `fit` is no longer rescaled to the viewport when it settles, so a drag never jumps in scale; `fit: true` frames a layout with the camera.
- A new `stateNetwork()` keeps the app's `lod()` request, as `data()` does.
- The both view no longer re-resolves its whole style on every streamed layout frame.
- The both view's physical nodes are outlined by a 1 px ring at every zoom, in a darker shade of their own fill (was a 1.5-world-unit black ring). New `InstancedCirclesData.bordersPx`: `borders` as screen-px ring widths on a world layer, applied in the shader.
