**LOD aggregates only where glyphs would overlap.** The cut now opens an aggregate as soon as its members' glyphs would not overlap on screen at the current zoom — each at its own radius, never smaller than half a pixel — whatever its footprint; `expandPx` keeps deciding how coarse the map is where members *would* overlap. One rule for every tree (`"spatial"`, `"structure"`, `"modules"`) and every graph size, with no node-count threshold: a small graph shows its nodes at the fit view, a large one still aggregates its dense regions, and a sparse corner of a large one opens first. In the Network Navigator, the 552-node `netscicoauthor2010.net` at the fit view now draws 454 nodes and 17 aggregates instead of 64 nodes and 105 aggregates (88 of which held members that did not overlap; now none do), while web-NotreDame (325k nodes) draws the same 279 glyphs at the fit view and 684 at 4×, with unchanged zoom-frame times.

Each tree node carries a new `clearZoom` — the zoom from which its members stop overlapping — computed with the layout and the style by `computeLODCrowding` (exact up to the zoom where the footprint rule opens the node anyway, `crowdingHorizon`), so the cut tests one number per node it visits. The engine runs the pass with every position + style pass on a main-thread tree, and the `"worker"` backend's spatial and structure streams run it per frame from the leaf style (`LeafStyle.crowding`); a drag or a position transition keeps the last values and recomputes them where the nodes come to rest. It costs about as much as the style pass with colours: ~35 ms at 325k nodes per streamed frame on the worker (the worker backend's web-NotreDame layout settles ~10% later; the GPU backend's is unchanged).

**Behaviour changes:** an aggregate whose members' glyphs do not overlap is drawn as its members, so views with sparse aggregates show more glyphs than before — most with `sizeMode: "world"` at scale, where members at least a pixel apart open (web-NotreDame at 4×: 13,280 glyphs instead of 606). A module of a single node is drawn as that node. `LODTree` has the new required `clearZoom` field (`Infinity` until a crowding pass runs, which keeps the old footprint-only rule), and the worker's LOD geometry buffer is `[cx, cy, extent, clearZoom]`.
