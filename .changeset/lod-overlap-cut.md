**LOD aggregates only where glyphs would overlap.** The cut now opens an aggregate as soon as its members' glyphs would not overlap on screen at the current zoom — each at its own radius, never smaller than half a pixel — whatever its footprint; `expandPx` keeps deciding how coarse the map is where members *would* overlap. One rule for every tree (`"spatial"`, `"structure"`, `"modules"`) and every graph size, with no node-count threshold: a small graph shows its nodes at the fit view, a large one still aggregates its dense regions, and a sparse corner of a large one opens first. In the Network Navigator, the 552-node `netscicoauthor2010.net` at the fit view now draws 454 nodes and 17 aggregates instead of 64 nodes and 105 aggregates (88 of which held members that did not overlap; now none do), while web-NotreDame (325k nodes, screen size mode) draws the same 279 glyphs at the fit view and 699 at 4×, with unchanged zoom-frame times.

Each tree node carries a new `clearZoom` — the zoom from which its members stop overlapping — computed with the layout and the style by `computeLODCrowding` (exact up to the zoom where the footprint rule opens the node anyway, `crowdingHorizon`), so the cut tests one number per node it visits. The pass prunes in two dimensions at any width — a module of thousands of members is indexed as the pass goes — so it costs O(tree size) plus O(m log m) per uncrowded module of `m` members: ~30 ms at 325k nodes, ~0.4 s for one 1M-member module. **While a layout runs, the cut uses the footprint rule alone:** the pass costs 0.35-1 s per frame at 2M nodes, so no streamed frame runs it. It runs once the layout settles (on the worker for the `"worker"` backend's and the GPU layout's spatial streams, whose settled frame carries it; on the main thread for a coarsening or module tree), when a layout is stopped, and with every later position + style pass on a main-thread tree (a structure stream is sent only the radii and size mode it needs). A drag or a position transition keeps the last values and recomputes them where the nodes come to rest.

**Behaviour changes:** an aggregate whose members' glyphs do not overlap is drawn as its members, so views with sparse aggregates show more glyphs than before — most with `sizeMode: "world"` at scale, where members at least a pixel apart open (web-NotreDame at 4×: 13,280 glyphs instead of 606, zoom frames ~6 ms slower at the median). A module of a single node is drawn as that node. `LODTree` has the new required `clearZoom` field (`Infinity` until a crowding pass runs, which keeps the old footprint-only rule), and the worker's LOD geometry buffer is `[cx, cy, extent, clearZoom]`.
