d3gl works two ways from React. It ships a thin React wrapper at
`@mapequation/d3gl/react` — the `<GeoMap>` component, which mounts the project-once
map engine for you — and, since the engine is plain imperative JavaScript, you can
also drive it directly from a `useEffect`. Both examples below render through the same
universal control bar as every other example on this site (backend switch, export,
live perf); the React component just receives `backend` and the canvas size as props.

## World map

`<GeoMap>` mounts the map engine and hands it back via the `onReady` callback, where
you add layers, enable zoom, and render once. It takes `width`, `height`, a d3-geo
`projection`, and an optional `backend` (`"webgl"`, `"canvas"`, or `"svg"`). When the
`backend` prop changes the component keeps the engine alive and calls
`map.setBackend()` — no remount — so the layers and the current zoom/pan are preserved.

## Phylogenetic tree

The same 64-tip rectangular phylogram as the vanilla simple-tree example
(`d3.link(curveStepBefore)` branches, `schemeCategory10` tip nodes), rendered from
React. Rather than a wrapper component, this drives the imperative `plot` engine
directly: a mount effect creates `plot(host, …)` once, builds the link layer and tip
points, enables zoom, and renders; a separate `[backend]` effect calls
`chart.setBackend()` so switching backend preserves the current zoom/pan; cleanup tears
it down with `chart.destroy()`. This is a valid, common pattern for using any
imperative engine from React.
